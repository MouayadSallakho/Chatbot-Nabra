**The visitor's chat (`shared/chat/`, new).** One launcher, one panel and one transcript for the widget, the hosted page and the settings preview. They are presentational: no credential, no API, no forms module. The panel has the header (agent name as the only `h1`, the honesty line with the AI glyph, New chat, Close), the transcript, the AI-only typing state (three dots in the AI tint plus the sentence), the handoff notice, errors and rate-limit warnings, and a composer where Enter sends, Shift+Enter adds a line, an IME composition is left alone, and the keys are stated to screen readers. Bubbles by sender: the visitor's own message is neutral, on the end side; the AI's reply has the accent tint and the agent's name; a person's reply has the person glyph and "Support" in Ember. Every message is `dir="auto"`, and markup a visitor types renders as text. Handoff lines ("A person from the support team joined", "<agent> is answering again") come only from real message authors. `visitor-copy.ts` holds the visitor's error sentences (the same honesty rules as before, now translated) and the rate-limit wait in full sentences per Arabic plural category.

**The widget (`features/embed`).**

- Rebuilt on the shared parts. The frame geometry, the 56 px launcher footprint, the bridge messages, the sandbox and the origin rules are unchanged; `widget-loader.spec.ts` still passes untouched.
- Opening focuses the message box. Escape closes and returns focus to the launcher. The launcher's name is "Chat with <agent>".

- Weight: no forms module, and SignalR loads only once a conversation exists (`PublicChatRealtime`, with a guard so a slow load cannot revive a stopped listener).

**Accent rules (`accent-color.ts`).**

- `checkAccent` replaces anything that is not `#rrggbb` with the default before it is used.
- The label colour falls back to black where neither near-black nor white reaches 4.5:1. Sea green `#2e8b57` had a 4.25:1 white label, a real AA failure locked in by the old spec. A new spec sweeps 4,096 colours and finds every label at 4.5:1 or better.

## 4. Decisions

1. **One shared chat, not three.** The widget, the hosted page and the settings preview render the same components. Rejected: restyling `embed-chat` and `hosted-chat` separately, as before, which had already drifted (different bubbles, different copy, different errors). Deferred: the 36.8 agent preview still draws its own copy with `.customer-view`; it should move to `ChatPanel` (open issue).
2. **The customer's bubble is neutral, the AI's carries the accent tint** (the brief), and a person is marked by glyph and word in Ember, as in the admin's two voices. The colour never carries the meaning alone.
3. **The hosted page wears Nabra's look** because its public read has no accent. Rejected: showing the widget's default blue there, which would claim a workspace colour that was never chosen. Backend ask 1.
4. **The settings preview follows the admin's own theme and says so.** Rejected: scoping the dark palette to the preview, which would add the dark token set to the global stylesheet every page downloads.
5. **Accent rules make any colour legible instead of refusing it**, and the screen explains what they did. Rejected: blocking a save, which the server would not enforce and which would leave existing widgets as they are.
6. **The launcher's corner is physical** ("Bottom right" is on the right in Arabic too), because the loader places the frame physically. Letting the host page's `dir` choose stays a backend ask from 36.3b.
7. **SignalR is loaded when there is a conversation.** The first send pays a small extra download (14.3 kB gzip) in exchange for a lighter first load for every visitor who never writes. Before sending, the code still waits for the listener to start, as before.
8. **No form element in the composer at all**, even on the hosted page, so the two surfaces behave the same and nothing can depend on `allow-forms`.
9. **Figures on the hub without plurals** ("Chat links: 3"): scannable, honest, and no plural forms to translate.
10. **No example conversation in the settings preview** (rule 5): it shows the greeting, or the real empty state, and the checks say the rest.

## 8. Risks and open issues

- **No real AI reply was ever seen** in the widget or on the hosted page (no provider, by rule). The typing state and the honest failure were checked; the reply bubble itself is covered by specs and by the Support bubble, which uses the same path.
- **The 36.8 agent preview still draws its own customer view** (`.customer-view` in `_authoring.scss`), close to the new widget but not the same component (11% versus 12% tint, its own composer). It should move to `ChatPanel` in a follow-up, which would also remove that global CSS.
- **The settings preview shows the admin's theme**, not necessarily the visitor's; the note under it says so.
- **A dark host page:** the launcher's edge guards a pale accent on white pages only. A very dark accent on a very dark website may be faint; the third check says so in words.
- **Arabic copy has not had a native review**, as in earlier phases. Plurals and the glossary are checked by script.
- **Synthetic data:** 10 website-chat conversations were added in Northwind by the flow checks, each taken over by the owner with one synthetic human reply (see the accounts file). The public start limit refused further starts from 127.0.0.1 for a few minutes.
- **The matrix "clipped" lead on the chat link screen at 768 and 390 px** is the install snippet's `code` inside its own horizontally scrolling region (keyboard-focusable via `appScrollRegion`). The same lead is in the before gallery; it is not clipped content.
